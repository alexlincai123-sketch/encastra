# Licensing

**Status: decided — proprietary. `LICENSE` at the root is the operative document; this one is the
record of how that was reached and what it forecloses.** The options below are kept because a
decision is only legible next to the ones it rejected. **None of them is on offer. Nothing in
this document grants anything**, and a reader of the now-public repository should take the
sections headed "Source available" and "Open source" as roads not taken, not as intent.

---

## Where it stands today

The repository is **public and proprietary**. `LICENSE` at the root states the terms: no general
right to copy, modify, redistribute or make derived works, with the viewing and forking that
GitHub's Terms of Service attach to any public repository acknowledged and bounded there.

`Cargo.toml` carries `LicenseRef-Encastra-Proprietary` — a valid SPDX reference to a licence that
is not in the SPDX list — and `package.json` carries npm's `SEE LICENSE IN LICENSE`. Both point
at the same file. They replaced `UNLICENSED`, which said the right thing (absence of a licence is
not permission; the default is no) but said it only to somebody who already knew that.

The workspace keeps `publish = false`. That is load-bearing beyond the obvious: `deny.toml` sets
`private = { ignore = true }`, so `cargo deny check licenses` skips the workspace's own crates
and scores only dependencies. Remove `publish = false` and the gate would try to identify a
bespoke licence with askalono against a 0.9 confidence threshold, and go red.

Making the source readable is what changed; what a reader may do with it did not.

## What the repository carries (added 2026-09-15, revised when the decision was made)

- `LICENSE` at the root: the operative terms.
- `NOTICE` at the root: points here and at `LICENSE`, and deliberately does not assert whose
  copyright it is — naming the legal identity (a person or a company) is a separate decision that
  has not been made.
- `docs/THIRD-PARTY.md`: every crate compiled into the shipped executable (Windows target,
  normal dependencies of the desktop crate) and every npm package bundled into the frontend,
  with version, licence and origin. Generated by `scripts/third_party.py` from `cargo metadata`
  and the installed tree; CI fails when it is stale. It is an inventory; what each licence
  obliges when a proprietary binary links it is a question for counsel.
- `deny.toml`: the allowlist of licences a Rust dependency may carry, with the reason each is
  there. Notably MPL-2.0 (file-level copyleft: unmodified use in a binary carries no source
  obligation beyond the MPL files themselves) and BSL-1.0 (Boost, permissive) are allowed with
  their reasoning written beside them; anything copyleft at the work level (GPL, AGPL, LGPL
  static) is absent from the tree and would fail the gate.

None of that is a licence. The two things that remain external are the choice of terms and the
identity that grants them — see `docs/RELEASE_CANDIDATE_READINESS.md` for how they block.

## What has to be decided

Three questions, in this order. The third one is usually what actually settles it.

1. **May somebody read the source?**
2. **May somebody run the binary, and under what terms?**
3. **May somebody build a competing product out of it?**

## The options

### Proprietary, closed source

Source stays private; the binary ships under an EULA.

- **For**: nothing given away; total freedom to change the model later; simplest to reason about.
- **Against**: no outside contributions, no scrutiny of the security model, and a component
  platform whose core nobody can read is a harder sell to the people most likely to adopt it.
- **Needs**: an EULA. A draft already exists in `apps/web/src/config/legal.ts`, marked as
  requiring review by counsel.

### Source available

Source is public and readable; commercial use restricted. Business Source License 1.1, Elastic
License 2.0, Functional Source License, or a bespoke licence.

- **For**: readable and auditable — which matters a great deal for a product whose entire claim
  is a permission model somebody should be able to check. Protects against a cloud provider
  reselling it.
- **Against**: **not open source**, and calling it so would be false. Some companies will not
  touch a non-OSI licence. BUSL's automatic conversion to an open licence after a fixed term is a
  commitment made now and honoured years later.
- **Needs**: a licence choice, a change date and a converted licence if BUSL.

### Open source

MIT or Apache-2.0 (permissive), or AGPL-3.0 (copyleft).

- **For**: the widest adoption, real contributions, and it is what a component ecosystem usually
  needs to become one — people write components for platforms they can inspect.
- **Against**: irreversible in practice. Code released under MIT stays available under MIT
  forever, whatever is decided later; the only thing that can change is the licence of future
  versions. Permissive licences allow a competitor to take it wholesale.
- **Needs**: **Apache-2.0 over MIT** if this route is taken, for the explicit patent grant —
  worth having in a product that defines a protocol other people implement.

## A relevant asymmetry

Closed → open is easy and can be done at any time.
Open → closed is impossible for code already released.

That argues for **not choosing an open licence in a hurry**, and for choosing one deliberately if
at all.

## What was decided, and what was not

**Decided: proprietary, source readable.** The repository is public; the licence grants nothing.
That answers the first two of the three questions above — a person may read the source, and may
run a build under the terms that ship with it — and answers the third with no.

**Not taken, and worth naming so nobody infers it:** an earlier draft of this document recommended
**Apache-2.0 for `packages/protocol` and `crates/encastra-protocol`**, on the reasoning that a
protocol becomes a standard only if others can implement it without asking. That reasoning still
stands on its merits, and it was **not applied**. No part of this repository is under Apache-2.0,
MIT, or any other open-source licence, and no split licence exists. Publishing the *format
specification* (`docs/PROJECT-FORMAT.md`) under open terms remains available as a separate future
decision; until it is made and written down, it has not happened.

The asymmetry above is why this order was chosen: closed can still become open later, and the
reverse is not possible.

## What is done, and what is still open

Done:

1. Decided, using the three questions above.
2. `LICENSE` added at the repository root.
3. `Cargo.toml` (`LicenseRef-Encastra-Proprietary`) and `package.json` (`SEE LICENSE IN LICENSE`)
   agree with it.

Still open:

4. A licence header policy, or a deliberate decision not to have one. There are no
   `SPDX-License-Identifier` headers in the tree today.
5. The npm side still has no licence gate; `cargo-deny` covers Rust dependencies only.
6. Counsel has reviewed nothing. `LICENSE`, the EULA and the marketplace terms are all drafted
   in-house, and a lawyer signing them off is a condition of a production release, not of a
   pre-release.
7. The NSIS installer still does not ship `NOTICE` or `docs/THIRD-PARTY.md`, which several
   dependency licences require of a distributed binary. Open obligation, recorded in
   `docs/legal/LICENSE_DECISION.md`.
8. Fonts pulled by `next/font/google` and self-hosted into the web build are not inventoried in
   `docs/THIRD-PARTY.md`, which covers the desktop dependency tree only.
